## Documented limitations, not hidden fixes

1. **Provider accounting contract:** missing/malformed usage can be normalized to zero while a reply is successful. A no-network synthetic response reproduced this behavior. The release owner separately checked positive parsed input/output counts across 253/937/237/1,031 successful cohort calls, but raw usage objects were not retained; the client must not be described as universally fail-closed. Preserve the measured source and harden adapters in a future version. [provider.py:138](../orgbench/provider.py#L138), [provider.py:143](../orgbench/provider.py#L143), [provider.py:154](../orgbench/provider.py#L154)
2. **Single writer required:** the CLI has no cross-process output-directory lock. Concurrent run/prepare/select commands can duplicate paid work or metadata writes even though final duplicate-grid checks close claims. Explicitly permit only one process per output directory. [study_v6.py:167](../orgbench/study_v6.py#L167), [study_v6.py:184](../orgbench/study_v6.py#L184), [study_v6.py:243](../orgbench/study_v6.py#L243)

See [known_limitations.md](known_limitations.md) for the usage contract, worker filesystem isolation, estimated input caps and external-validity bounds. Final fresh tests, public metric replay and staged/manifest verification are separate release-owner checks; this code review does not substitute for their execution.
