# 2026-11-03：验收与执行隔离修正后的工具组织实验预注册 v5

本协议在首次v5模型调用前固定。继承 [v4协议](protocol_v4.md) 的候选组织、强基线、开发选择方法、单题预算、模型模式、统计比较和研究范围；v4文件不修改。所继承v4的SHA256为 `26E06DEE7682398B3C967A4106561B5724745B2387D890D393C6A4497186FF70`。

用户继续实验且不设总预算的授权保持有效；API实际余额、服务健康与单题预算仍是运行条件。取消人为总费用上限不表示无限追加统计样本，不为获得正结果重复使用确认题目。

## 修订原因与旧数据

v4独立审查发现：公开规格要求不修改输入，但原解释器只对输入深复制，没有检查候选是否修改了该副本；加入输入变异的参考程序仍能通过公开和隐藏输出测试。此外，AST层协作式deadline不能覆盖所有原生容器比较、序列化等宿主操作，需要宿主进程强制终止与内存限制。解释器对 `isinstance(None,type(None))`、容器方法作为排序key、增量赋值下标单次求值等受支持语义也需与Python一致。

因此停止旧 `tools_dev_v4`，只保留为debug记录；它不再用于正式选择候选，不与v5开发或确认合并。已经生成但未实际调用的v4确认题池也不作为v5确认题使用。所有旧请求、源程序、失败、资源消耗及修订原因留档。

这些变化是确认前的安全、验收及兼容性修正，不依据确认集质量调组织或门槛。路由阈值25保持不变；18到25的旧修正发生在v4新模型开发结果之前，不能误称是v5质量驱动调参。

## 任务与共同验收

仍使用三族生成型代码修复：版本/来源冲突合并、幂等状态机账本、条件依赖配置规则。每道题包含固定公开语义、错误starter、3个公开测试，独立终局评估使用30个私有测试。模型只能读取公开部分；私有测试、参考答案与最终评分不反馈给求解组织。全部私有测试通过才算该任务全对，另报告通过比例。

新增共同的输入不可变契约：调用 `solve(payload)` 不得修改传入的payload或其嵌套可变对象。解释器在候选调用前保留独立快照，调用后在外部比较，发生变异则验收失败，即使终局返回值恰好正确也不能通过。不得通过候选自己的“未修改”声明作验收。该要求写入所有族的公开规格，并对所有组织的公开/隐藏测试一致执行。

候选代码继续只在有限AST子集内解释；不把生成的代码交给Python的exec/eval执行，也不允许import、任意属性、文件、网络或shell。修复受支持的基础语义，不悄悄放宽为任意Python。公开测试和私有测试用相同解释器规则；参考实现与手工边界测试在模型运行前验证。

## 宿主执行隔离与资源界限

每次公开3例或隐藏30例的**整批验证**，在一个独立 `python -I -S` 子进程执行；单payload的 `run_candidate` 同样隔离。批内保留2秒协作式deadline；每payload保留250000 AST fuel。宿主对单个子进程的导入、IPC、验证与输出整体设置5秒硬超时，超时后kill且不自动重试，覆盖协作deadline不能中断的宿主操作。

固定资源参数：

| 项目 | 限额或规则 |
| --- | --- |
| 每验证子进程内存 | 256MiB |
| Windows限制 | Job Object的进程内存限制、ActiveProcessLimit=1、KILL_ON_JOB_CLOSE |
| 不能安装限制时 | fail closed，不退回无界执行 |
| 子进程stdout | 最多256KiB |
| 子进程stderr | 最多16KiB |
| IPC输入 | 最多2MiB有限JSON |
| 宿主硬时限 | 每次整批验证5秒，包含启动与IPC |
| 子进程环境 | 最小环境；不继承API认证等任务无关凭据 |

候选违反时间、fuel、内存、输出界限或输入不可变契约属于可审计的候选验收失败。隔离器无法建立、宿主启动/通信系统错误等基础设施异常应单列，不能误当候选推理错误。进程与资源限制属于防御措施，不宣称是执行任意恶意Python的生产级安全沙箱。

## 模型、共同工具与五种组织

统一 `deepseek-v4-pro`，主实验非思考模式，温度请求/有效值0.3。每个任务/组织运行最多5次逻辑模型调用、累计12000输出Token、32000输入Token估算预检；实际usage与超限单独记录。路由、报告、审计、整合和修复全部计入。各组共享相同规格、starter、公开例、语法检查与公开执行反馈；相同资源上限不等于相同实际成本。

1. `single_tool`：一次可用全部剩余输出；真实公开测试全部通过即停止，只在失败时按固定预算修复，不强制冗余自检。
2. `hierarchy_tool`：路由、两个隔离报告、完整代码整合，必要时最多一次公开失败修复。
3. `bazaar_tool`：两个隔离完整候选、同一公开测试、固定排序选择和失败触发修复。
4. `contract_team`：初始完整程序、强制独立审计、结合实际公开失败和未验证疑点修订；公测不退化时按固定规则选择修订版本，必要时修复。
5. `adaptive_tools`：只依据公开spec/rules的叶子计数、条件词计数及依赖词计数确定性路由；`score = leaves + conditionals + 2×dependencies`，阈值固定25，达到阈值走契约团队，否则单体，不读取family字段或隐藏分数。

路由是手写原型，不是学习或原创组织理论。当前三个模板的分数分别为版本族20、账本族30、配置族18，因此在这个生成器中实际等价于账本走团队、其余走单体；不宣称已识别样本级难度或证明跨模板泛化。

审计模型提出的反例或预期值始终是未验证假设，不能当外部oracle，也不能替代真实公开测试期待值。只有真实公开失败可标为实际工具反馈。

## 新数据、选择与固定运行规模

**开发**：新seed `2026110303`、split `dev`、每族5题，共15个独立任务；五组织各一次，共75个运行。只从 `bazaar_tool`、`contract_team`、`adaptive_tools` 中选择一个候选：完整隐藏成功数最高，同分时总输入+输出Token最少，再按名称排序。两种基线不参与候选选择。选择文件保存开发结果、代码与协议指纹；基础设施污染或不完整的开发集不得用于选择。

**确认**：新seed `2026110304`、split `holdout`、每族30题，共90个独立任务；冻结候选、`single_tool`、`hierarchy_tool` 各一次，共270个唯一运行单元。可提前生成题目，但在候选选择冻结前不调用确认模型，也不根据确认结果修改求解或路由。

固定外层4并发，内部调用仍串行，运行顺序随机交错。生成seed不控制供应商采样。开发/确认使用不同输入与规则种子；同一个生成模板换seed不是现实仓库的分布外验证。

正式模型调用前冻结全部代码、测试、提示、数据、协议和配置；确认阶段不改候选、强基线、执行/验收、样本数、预算和统计门槛。若发现必须修正的基础设施/验收错误，保留全部记录并另立新版本与新确认数据，不能覆盖旧文件或把有利旧结果混入。

## 事先固定的质量检验

总体三族等权，主质量指标为完整任务全对成功。两个主要质量比较为“冻结候选减 `single_tool`”和“冻结候选减 `hierarchy_tool`”，按独立任务配对，用精确符号置换和题簇bootstrap成功率差区间；两项p做Holm校正，阈值0.025。对应差值为正、95%区间下界为正且校正p<0.025，才能确认相对该对照质量提升。

两项都通过才说在此实验范围超过两个指定对照；只通过一项须具体点名，不扩大为全面胜出。完整性按任务/组织/重复键唯一、三个组各90题检查。缺失、基础设施污染或失效标记阻止确认；不删除坏样本再选赢家。

## 效率检验与新增可用性门

效率只对 `single_tool` 比较，原非劣容限5个百分点、最小总Token节约15%保持不变。对每个独立题目，若候选成功均值低于基线记loss=1；使用单侧97.5% Clopper–Pearson上界估计P(loss)，作为成功率下降幅度的保守上界。按题配对重采样总输入+输出Token比，使用双侧95%bootstrap区间的上界。

确认效率改善必须同时满足：

1. 完整且无基础设施污染，候选与基线均没有未知usage。
2. **新增可用性门**：候选和基线各自观察到的独立题目平均成功率均≥50%。不把两组都失败但少花Token称为有用效率改善；这个门不替代不确定性检验，也不表示总体成功率已被保证高于50%。
3. loss概率单侧97.5%上界≤0.05。
4. 总Token比95%区间上界<0.85。

90题零loss的CP上界约4.02%；9题零loss不够。重复采样不能增加独立题数。效率结论只是“本任务分布上，固定5pp容限内且至少15%总Token节约”，不是严格Pareto、精确等质或现实应用必然可接受的质量退化。

`decision.py` 输出双方观察成功率、50%门阈值及是否通过等明确标记。质量检验不受这个效率可用性门影响：相对低成功基线取得真实质量提升仍可按原质量规则判断。未知usage阻止资源/效率确认；最终终局得分已知、完整且无基础设施污染时，质量比较不以未知费用替代正确性证据。

## 名义错误率与报告范围

质量比较族按名义α=0.025做两项Holm控制；效率以质量非劣和成本节约的交并规则分配名义α=0.025，两类使用Bonferroni分配总名义α=0.05。Clopper–Pearson在独立题目二项模型下是精确上界；bootstrap是近似区间，没有有限样本精确覆盖或总体FWER精确保证。不得把名义分配表述成无条件有限样本保证。

观察Pareto前沿只作描述，不能替代上述规则；没有通过门槛写证据不足。输入+输出Token是事先固定的资源代理，不等于费用；另报输入、输出、缓存、HTTP尝试数、逻辑调用、延迟及固定价格表重算的估计费用。不事后挑有利指标改主目标；延迟不宣称内部并行加速。

## 服务错误与停止

外层4并发。只对明确HTTP429拒绝最多重试2次，等待3秒/10秒，每次尝试全部保留日志；未知超时/传输错误不自动重试。逻辑模型调用与HTTP尝试分开统计；先前失败尝试若usage未知，最终响应成功也不能假定重试免费，必须将未知计量传播到资源确认标记。

连续3个最终基础设施错误后锁存停止新派发，迟到成功不解除；在途运行收尾并落盘。正常格式、语法、公开测试、候选资源限制或逻辑失败是合法观测，不借它们停止劣势样本。余额/服务异常不能解释为组织推理失败，也不自动充值。

主实验应在可解析、非全地板的开发设置下按预定规则完成确认。此后的模型/思考模式/任务模板迁移另用新seed与冻结规则，不回填本次确认。结论限于该合成代码任务、模型、受限解释器和已测组织；不证明普遍最优，也不声称已复现或超过官方DSH的持久化多任务系统。
