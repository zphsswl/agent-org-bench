# v6评测路线建议：补强对照，再研究按任务组织

本文件是只读审查后的研究建议，不是已开始的新确认协议。没有调用模型API，没有修改orgbench、旧协议、数据或开发选择。v5的有效确认结论保留；已看过的v5留出集以后只能用于描述、错误分析和提出假设，不能再确认新策略。

## 建议继续，但先回答增益来自哪里

v5证明了一个限定结论：同一DeepSeek模型、同一工具和资源上限下，固定候选 `adaptive_tools` 在该合成代码任务分布上，质量优于公开测试通过即停的单体和简化层级。它尚未证明新组织优于等预算自审单体，也没有确认省Token或普遍最优。

下一轮最有价值的工作是区分额外复核、提示策略、上下文组织、预算分配与路由选择的贡献，而不是继续给Agent更换社会身份。若等预算单体自审能解释大部分提升，这也是明确的研究成果：有效机制是验证/复核，不必归功于新的组织理论。

## 一、最重要的混杂与必要对照

### 1. 缺少计算匹配的单体自审

当前 `single_tool` 公测通过即停；`contract_team` 即使公测通过，也必须执行独立审计与修订。二者有相同最大预算，但实际复核机会和调用轮数不同。v5的对照适合比较可部署策略，不能单独识别“多Agent组织”是否优于“多花一次复核”。

必须增加 `single_self_review`：完整初稿→同一单体自我批评→修订，初稿/批评/修订采用与契约团队相同的阶段额度、共同公开反馈和至多相同修复次数。它是计算匹配的机制对照；原来的公测即停单体仍保留为实际成本强基线，不能用强制多轮单体替换它来制造节省。

还要固定每阶段看到的信息，而不只是名字。当前模型接口每次调用本质上是无状态请求；“自己的审查”和“独立审计”若接收完全一样的spec与源代码，只改角色名称，就主要是提示词对照。真正的上下文区别必须写清：自审保留哪些初稿过程/历史，独立审计排除哪些锚定信息，修订收到哪些真实测试结果。它们都不能读取隐藏真值。

主结论应同时报告质量—实际Token曲线，不能把共同预算上限写成相同消耗。可以额外设置两个预先固定的总预算档，但同一档内全部组织的模型、工具、公开信息、修复权限一致；不在看完留出结果后挑对候选最有利的预算档。

### 2. 当前路由其实是模板选择

v4公开规格的分数为版本20、账本30、配置18。v5统一加上不可变payload条款后，**冻结记录中的真实分数为21、31、19**，每族所有题都恒定。阈值仍为25，所以实际路由没有变化：账本用契约团队，另两族用单体。v5协议中的旧数字应作为文字勘误在新文档解释，不能改动旧冻结协议或重算其结果。

“不读取family字段”不等于“不是任务类型代理”。固定模板用词完全决定分数，因此目前没有验证样本级难度识别，也不能解释为在线自组织。新路由需要真实变化的公共结构特征，例如依赖深度、冲突率、规则相互作用、公测覆盖率和实际失败信号；在开发集拟合后冻结，再去全新任务检验。

需要保留总是单体、总是团队及随机路由作为路由消融。随机路由只使用预先固定的随机流；不能按隐藏分数选路。逐题“事后最优架构”可以展示为oracle上界，但它不能充当可部署路由，也不能参与实际胜出结论。

### 3. 增益主要在账本，其他两族使用同一实现

以下是对已公开v5结果的后验描述，不是新的确认检验：

| 任务族 | 候选全对 | 单体全对 | 候选独对/单体独对 | 净提升 |
| --- | ---: | ---: | ---: | ---: |
| 版本 | 24/30 | 22/30 | 4 / 2 | +2 |
| 账本 | 25/30 | 9/30 | 16 / 0 | +16 |
| 配置 | 17/30 | 13/30 | 6 / 2 | +4 |

总体多22道正确中，账本贡献16道，即72.7%的净增量。版本与配置在候选和单体中实际运行相同函数和提示链，只是独立采样；这两族的差异不能归为不同组织结构的贡献。v5的整体随机化比较依然成立，但“为什么有效”的因果解释需要下一轮消融。

尤其应在账本族加入计算匹配自审。如果普通自审同样改善first-seen/first-applied、全局/前向取消等问题，就应收缩到复核机制；若独立上下文持续更强，再研究减少锚定和错误传播的组织机制。

## 二、独立核验：rules确实跨seed变化，但不是任意新任务

已检查 `_rules` 的真实计算：

`n = SHA256(seed, split, family, 'semantics')的整数值 + index`。

规则选项再由n的余数与整数除法解码。因此它不是仅按index取模、只让seed改变输入数据；seed和split确实改变规则。但它是有限规则循环的相位平移：

| 任务族 | 规则组合周期 | 本次离线检查 |
| --- | ---: | --- |
| 版本 | 96 | 对完整周期逐项验证 `rules(i)==rules(i+96)` |
| 账本 | 64 | 同样验证64周期 |
| 配置 | 128 | 同样验证128周期 |

真实v5开发（seed2026110303，split=dev，各5题）与确认（seed2026110304，split=holdout，各30题）中，每族对应前5个index的规则相同数为0，开发5个规则与确认30个规则集合重叠数也为0。这说明当时的“新输入/新规则”说法有依据。

但连续index在语义空间中相邻，部分高位选项可能在一批题中几乎不变；新seed仍只重新组合这些已知原语，不是新算法类型、未知组织问题或现实仓库迁移。一个周期跑满后，不同seed的规则集合还会相同，只是相位和测试payload不同。

下一轮应显式记录规则覆盖表，分层采样语义组合，而不是假定多换seed就获得广泛独立任务。可设计两个单独测试层：未见规则组合的组合泛化，以及全新规范模板/真实代码库的分布外验证；不要将二者混称。

### 全局状态检查

离线实测未发现跨候选污染：

- 先生成开发集、再生成另一seed的确认集、再重生成原开发集，任务内容相同。
- 在审查进程内修改一个返回任务的rules字典，不会污染下一次生成；没有修改任何留档任务。
- 定义带模块全局计数器的候选，分别调用两次隔离执行器，结果均从1开始，说明独立运行不会继承前一个候选的模块状态。

生成器使用局部 `random.Random` 与SHA256随机流；参考实现输出顺序有明确排序/输入顺序规则。候选在每payload都有新解释器/隔离执行上下文，不能依赖跨用例模块缓存来完成题意。这是此基准的执行语义限制，不是已经发现的多候选全局变量bug。

## 三、建议的8策略开发筛选

以下是机制原型清单，不意味着复现任何同名论文或框架：

| 策略 | 比较目的 | 必须真实实现的差异 |
| --- | --- | --- |
| `single_tool` | 最便宜的工具单体强基线 | 全部剩余额度、公测通过即停、失败修复 |
| `single_self_review` | 无新组织的等预算复核强对照 | 与团队匹配的初稿/批评/修订额度、明确同体历史 |
| `hierarchy_tool` | 常用中心编排风格 | Router→隔离报告→整合→公开失败修复 |
| `fixed_dag_tools` | 确定性流水线风格 | 固定阶段与依赖，去掉模型派工决策 |
| `bazaar_tool` | 独立采样/竞争候选 | 隔离完整分支、统一公测与固定选择，不能隐藏分数挑最好 |
| `blackboard_tools` | 共享产物/共迹协调 | 版本化共享代码、发现、证据与验证状态，而非只换角色名 |
| `contract_team` | 独立审计机制 | 初稿、与作者上下文分离的审计、证据修订 |
| `adaptive_tools_v6` | 可见任务特征选择机制 | 冻结的真实可变特征与动作，保留旧v5路由作描述性迁移点 |

如果本轮不准备改变路由，第8臂就直接运行原 `adaptive_tools`，不能把它改名v6当作新算法。若新增市场、多中心治理或控制论，下一轮另设机制与适合的资源争用/故障任务，不把它们塞成当前静态函数题的职位提示词。

随机路由、总是团队等可以作为候选路由的附加消融。它们须在协议中预先列出数量和预算，不在看到留出成绩后才选择有利消融。预算有限时优先保留两种单体、独立采样、独立审计，减少次要社会隐喻组。

## 四、按任务建立适用图，不按架构名称宣布总冠军

| 可观测任务轴 | 建议分层 | 验证的问题 |
| --- | --- | --- |
| 顺序依赖 | 状态独立 / 短链 / 深链与回访 | 团队是否真的比连续单体推理更合适 |
| 信息冲突 | 无冲突 / 权威时间冲突 / 撤销与例外相互作用 | 独立复核何时有增量 |
| 可分解性 | 一体函数 / 独立模块 / 跨模块耦合 | DAG、分叉、黑板能否利用真实分工 |
| 公测覆盖 | 高覆盖 / 关键边界缺失 / 仅烟雾测试 | 审计收益是否只是补公测漏项 |
| 共享资源与状态 | 无争用 / 并发修改 / 故障重试与幂等 | 自治、租约、反馈控制的实际意义 |
| 输入规模与工具密度 | 小 / 中 / 接近资源界限 | 协调税、上下文与执行预算何时主导 |

同一族内部也必须跨这些轴变化，避免复杂度分数仍是模板标签。加入新规范模板或多文件代码修复时，所有组拥有相同公开工具和测试能力。固定难度门防止全地板/全天花板；原生单体9/9的pilot只说明当前小样本有天花板，不证明新模型普遍更强，也不能拼入DeepSeek数据。

任务适用图首先报告每层成功率、配对差、成本点和区间。若要宣称某组织特别适合某轴，应预先写出交互/分层假设并分配多重比较预算；不能从几十个格子里事后挑高点。开发集选出的路由须在完整新留出集整体检验，不能在同一留出集中一边找“逐题最优”一边报告部署收益。

## 五、有限的新协议建议

### 开发与选择

建议8策略×每族6个新开发题×3族×1次=144个开发运行。题目按语义组合和任务轴分层，不只沿一个规则循环取连续片段。只在开发阶段完成解释器/公测检查、阶段额度匹配、错误分析和路由训练。

从非基线策略中按预注册的质量优先/成本同分规则选一个候选，冻结候选、提示、特征、参数、协议、代码及数据hash。`single_self_review`、`single_tool` 以及其他必要基线不参与“新架构候选”选择，避免用留出再次挑对手。

### 新留出与N

一个较扎实的默认计划为300个独立新题、每族100题，四臂：冻结候选、`single_self_review`、`single_tool`、`hierarchy_tool`，各一次，共1200个确认运行。两个主要质量对照建议改为计算匹配自审和公测即停单体；层级作预先指定的描述性常用对照。若层级也要作主要检验，必须事先扩展检验族与校正，不能继续套用两项Holm。

300题并不保证检出很小效应：配对不一致率q≈0.2—0.3时，约10个百分点提升通常需要约200—300个独立题目的量级；5个百分点可能需要约800题或更多。开发集估计题目簇方差后，在首次留出调用前一次性固定N；不能看到p值后增样。重复用于估计采样稳定性，不能当新增独立任务。

若单独研究账本审计机制，主要分布就应明确聚焦账本并准备足量独立账本题，另两族作迁移测试。把100个受机制处理的账本题和200个同实现题相加，不等于有300个关于审计机制的独立证据。

### 指标与成功门槛

- 主质量：隐藏用例全部通过的任务成功率；次要指标为隐藏比例、公开→隐藏泛化差、公测通过后的潜在回归率。
- 资源：实际输入/输出/缓存、逻辑调用、HTTP尝试、审计/管理占比、每成功成本及端到端延迟；同时展示质量—资源曲线和描述性Pareto前沿。
- 机制：初稿→审计→修订的公开改善、最终隐藏改善/回归，只在提交完成后离线分析；审计声称的反例不当真值。
- 完整性：缺格、基础设施错误、预算超限、未知usage单列；不删失败来制造优势。

可沿用v5的名义α分配、质量Holm2、5pp容限/15%节约、双方观察成功≥50%的效率门，但先确定主要对照和目标分布。成本bootstrap仍是近似覆盖。质量未显著不等于等质；Token点估计下降不等于确认效率或严格Pareto。

模型后端必须分别统计；本次DeepSeek额度耗尽后不再调用、不再要求充值，按用户边界改用原生Agent。原生solver须fresh fork且只拿PUBLIC；原生实际Token/费用未知时保持null，禁用Token效率确认，不把两后端合并成一张优越排行榜。

## 六、常用架构和真正复现的命名

ReAct风格工具单体、Supervisor–Worker、固定DAG、独立集成、黑板、审计团队属于组织模式。当前本地实现应命名为“某模式的统一预算简化实现”，不能称AutoGen、CrewAI、LangGraph、DSH、G-Designer或GPTSwarm的官方复现。

只有真正运行其官方代码/推荐配置、固定版本和提交、记录原始任务/工具/模型映射，并说明改动后，才可写“框架集成基线”或“论文复现实验”。同一框架也能表达多种组织图；框架名不是组织结构自变量。建议分别维护 `pattern_baselines` 和 `official_integrations` 两张表，空白项明确未运行。

DSH的持续在线、多Ticket、事件订阅、持久化和人类注意力收益需要事件到达、任务生命周期、工具副作用及人工介入统计的另一套基准。本轮纯函数代码题不能宣称超过完整DSH。

## 七、GitHub项目应先成为可复现实验平台

建议项目定位为“Agent组织机制构建与评测实验室”，不是“已找到最优Agent社会”。至少提供：

- 统一模型适配、组织策略接口、预算/尝试记账、确定性工具与隔离执行器。
- 公开开发任务、退休基准release、独立留出生成与只读评分边界。
- 协议/选择/数据/代码/答案hash清单、完整失败与失效记录、离线统计重算脚本。
- 离线单元测试和CI；默认不会调用付费API。`dry-run`、`prepare`、`replay`、`analyze` 与真实付费运行明确分离。
- 每个组织的实际消息图、可见状态、停止规则和阶段额度，避免只有角色提示词。
- README写明v5有条件质量优势、效率未确认、路由实际模板性与真实框架尚未复现。

公开采用允许列表：代码、文档、公开示例、脱敏汇总、版本化已退休v5数据和复算所需产物可以审阅后发布。不能直接把整个 `runs/`、原始API日志、账户/余额文件、认证头、`.env`、native评分密钥或当前活跃隐藏用例推到仓库。发布原始日志前扫描密钥及绝对个人路径。

活跃留出的private cases、可重建它们的seed和评分密钥不进公共仓库；只公开hash承诺，评分完成/退休后按明确release政策公布。生成器和参考实现开源后，若还把活跃seed公开，所谓隐藏测试很容易被重建；加密同目录也不等于对同身份Agent的OS权限隔离。真正盲测要有执行/数据边界和可审计上下文。

先完成本地离线复算和文档，再在用户授权的GitHub仓库发布可审阅结果。最终可以成为有论文复现与常用基线的研究项目，但所有“更好”都需注明任务、模型、预算与对照，不能宣称universal best。
