# v6：组织机制、计算控制与任务适用性预注册

本协议在首次 v6 模型调用前固定。v5 数据只作历史证据和探索性拆分，不参与本轮确认或门槛调参。既有 v5 数据、协议、代码快照与结论保留。

## 问题与范围

继续研究有价值：v5 只确认了一个手写路由策略相对强单体、简化层级组在三个生成型代码任务族的质量优势，不能区分额外审查轮次、独立信息上下文与任务路由的贡献，也没有确认成本优势。当前公开规格复杂度实际为版本21、账本31、配置19；旧协议20/30/18漏计了统一输入不可变后缀的一个must，三组都加1，阈值25的路由不变。

本轮构建可复现的机制比较，不声称复现DSH、AutoGen等完整框架，不声称寻找到了普遍最优组织。真实软件仓库、浏览检索、长时程工具任务、异构模型和跨域迁移仍属于未来外部效度检验。

## 任务与独立抽样

沿用已验证的三族任务定义、受限AST解释器、输入不可变契约、每题3个公开与30个私有终局测试。隐藏案例和分数不能进入求解、审计、修复、选优或路由；不执行模型生成的任意Python。

新 `task_suite_v6` 为每个 `(root_seed,split,family,index)` 通过SHA256独立派生128位task_seed，再在旧生成器中取该族index0。这样不再对同一随机相位的连续规则编号取样。各族规则支持仍有限（96/64/128种），可能重复规则；不主动排除开发/确认语义重叠，因为目标是同一有限合成人口的独立抽样。公开输入和隐藏payload使用不同visibility种子。相同模板换seed不构成真实分布外验证。

任务suite_hash使用保留映射插入顺序的紧凑UTF-8 JSON做SHA256；配置patch键的迭代顺序可能有语义，不能用sort_keys标准化后声称已覆盖所有任务语义。任务文件写入亦保留顺序。

## 九个实现与资源公平性

共同模型 `deepseek-v4-pro`，非思考模式，温度0.3；每个cell最多5次逻辑模型调用、累计12000输出Token、32000输入Token估算预检，实际超限、未知usage单列。外层4并发，内部阶段串行，cell顺序固定种子随机交错。供应商随机采样无法用本地seed控制。相同上限不是相同实际开销。

| 名称 | 机制 | 本轮用途 |
|---|---|---|
| plain_single | 一次完整源代码提案、公测后停止，不修复 | 无新增组织基线，开发描述 |
| single_tool | 公测全过停止，仅真实失败触发修复 | 强单体次要对照 |
| single_self_review | 同一求解者完整历史的初稿→自检→修订，必要时失败修复 | **主要对照** |
| hierarchy_tool | router→两份隔离分析→代码整合→必要修复 | 常用层级机制次要对照 |
| best_of_three | 三份独立完整代码，公测排名择优、固定分支号破同分、必要修复 | 多候选采样次要对照 |
| bazaar_tool | 两份独立完整代码、公测择优、失败修复 | 候选 |
| contract_team | 初稿→独立审计→修订、失败修复 | 候选 |
| adaptive_tools | 固定公开spec/rules分数>=25走contract，否则single | 候选；仍等价任务模板路由 |
| evidence_gated | 初稿→真实公测；先有限修复，或按固定公开静态特征升级审计/修订 | 候选 |

`single_self_review` 与 `contract_team` 匹配三次必需调用及60%/10%/剩余的阶段输出配额、公开不退化时优先修订的选择规则。自检保留完整历史，独立审计仅看公开任务与待审代码；上下文不同正是操纵因素。自检实际输入用量可能更大，输出也未必用满，必须报告实际Token，不能称严格同成本。

best-of-three每分支最多总输出上限25%，余量用于公测失败修复。它是best-of-N，不能称多数投票。plain_single只有一次调用，故不能独自用来证明组织机制有贡献。

evidence_gated固定：初稿最多60%；第一次公测失败时给20%进行一次真实失败修复，若修好立即停止；否则仍失败或首次通过但静态风险触发时独立审计10%后修订。静态风险为公开spec中if/unless/only/except/otherwise/must条件词>=6，且候选代码AST分支<3或非空行<24。阈值在新开发API调用前固定，不按旧留出分数拟合；这是粗糙覆盖启发式，不是正确性/不确定性oracle。任何审计反例和期望值仍是未验证假设，不反馈伪造的真实测试。

## 固定样本和选择

开发seed **2026110306**，split dev，每族3题、共9题，九种实现各一次，共81cells。小开发集的选择噪声需披露。候选仅四种：bazaar_tool、contract_team、adaptive_tools、evidence_gated。选择完整隐藏成功数最多者；同分总实际输入+输出Token最少，再名称排序。只有完整唯一网格、无基础设施污染且usage完整时才能冻结。保存结果、代码、协议hash。

机器可读计划为`docs/study_v6_plan.json`，同时冻结plan_hash并归档。未传seed/per-family时从该阶段的已注册计划解析，不沿用开发默认值；显式样本数、模型、预算、模式、并发或臂名单与计划不符即拒绝。清单记录不含认证的HTTPS API基址，恢复时更换服务地址亦拒绝。

确认seed **2026110307**，split holdout，每族20题、共60题；冻结候选+single_self_review+single_tool+hierarchy_tool+best_of_three各一次，共300cells。首次确认模型调用前冻结候选、代码和统计方法。plain_single已在开发中作为描述性对照，不再加入确认：主要研究问题是相对强基线的增益，不能将开发差异当作独立确认。

确认期间不增样本至显著，不换候选/修门槛/只重跑模型错误，不以旧留出做新确认。发现必须修复的验收或基础设施问题时保留并失效本版本，另立协议。实际账户额度耗尽后停止DeepSeek，不请求充值，原生Agent另开数据/模型cohort，不能拼接补齐。

## 统计与结论

主要指标：单题30/30隐藏全对。主要比较候选对single_self_review，双侧任务配对精确符号置换p<.025，同时平均差>0且95%配对任务bootstrap区间下界>0，才声明主要质量优势。次要三项（single_tool、hierarchy_tool、best_of_three）在独立家族内Holm校正，alpha=.025，仍需正平均差/正区间下界。两族名义FWER总额.05。主要/次要结论分别报告，不能因为某一项失败就隐去其他结果，也不把赢过弱基线当作赢过主要强对照。

任务而非案例/重复API请求是抽样单位。60题每族固定20，bootstrap对配对任务抽样；每族分析及公开规则切片只探索性描述，报告样本数和配对四格，不据此宣称预先确认的任务条件效应。报告隐藏通过率、真实公测通过但隐藏失败、退化/修复/审计频次、实际输入/输出/缓存Token、逻辑调用与延迟；Token比和配对区间只描述，本轮不设置“效率确认”门。

任何缺cell、重复/额外cell、基础设施错误、未知usage、实际预算超限都关闭确认声明，保留全部观察值。失败不随意剔除或以原生模型替换。HTTP429仅明确拒绝时最多重试两次（3/10秒），每次记录并将先前usage标未知；网络等不明确失败不自动重试。三次连续基础设施错误触发运行熔断；外部额度守护器监测明确HTTP402。
